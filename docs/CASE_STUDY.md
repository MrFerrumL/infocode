# Инфокод: кейс разработки

[Обзор проекта](../README.md) · [Архитектура](ARCHITECTURE.md) · [Скриншоты](SCREENSHOTS.md)

## Задача

Собрать рабочее пространство подготовки к ЕГЭ, в котором практика ученика связана с программой курса и действиями преподавателя. Нужен не только каталог: преподавателю важно выдавать работы, понимать трудности группы и возвращать ученика к нужной теме.

В проекте два основных сценария:

1. **Самостоятельная подготовка:** выбрать номер → изучить условие → ответить → посмотреть обратную связь → решить похожее.
2. **Занятие с преподавателем:** подготовить материал → назначить группе → получить ответы → проверить и спланировать повторение.

## Что реализовано

| Направление | Результат в приложении |
|---|---|
| Практика | Полные условия в каталоге, ответы без перехода на отдельную страницу, история и разбор |
| Учебный контент | Курсы из разделов, уроков и шагов; блочные материалы; библиотека конспектов и импорт Colab |
| Оценивание | Тренировочные варианты с серверным сроком, сохранением ответов и правилами баллов |
| Преподавание | Ученики, группы, назначения, повторные попытки ДЗ, аналитика и календарь |
| Два предмета | Отдельные материалы информатики и физики при общих аккаунтах и группах |
| Интеграции | Проверка ФИПИ, API банка для отдельного сервиса КР и подписанный вход преподавателя |
| Эксплуатация | Docker Compose, HTTPS, проверки работоспособности, копии данных и установка на VPS |

## Почему такая архитектура

### Django и серверный интерфейс

Проект состоит прежде всего из форм, связанного учебного контента и разграничения доступа. Серверный рендеринг сохраняет эти правила рядом с моделями и валидацией. JavaScript добавляет редактирование блоков, проверку ответов и календарь без отдельного SPA-приложения.

**Компромисс:** интерфейс тесно связан с серверными шаблонами. Это упрощает текущий стек, но для отдельного мобильного клиента потребовался бы более полный публичный API.

### Общая платформа для двух предметов

Пользователи и группы не дублируются. Предмет выбирается в сессии, middleware устанавливает контекст запроса, менеджеры моделей ограничивают выборку. Отдельный менеджер позволяет явно работать со всеми предметами в административных сценариях.

**Компромисс:** служебным командам и фоновым операциям необходимо явно учитывать предметный контекст. Проверки изоляции предметов находятся в `learning/test_physics.py`.

### Стабильная история обучения

Редактирование урока не должно уничтожать прежние ответы. У шагов есть версии, а выданные варианты хранят снимки заданий. Изменение проверяемого содержания может потребовать повторного прохождения, сохраняя историю предыдущей версии.

Это разделяет два вопроса: «что ученик решал раньше» и «прошёл ли он актуальный материал».

### Практика с обратной связью

Обычный ответ проверяется на сервере. Каталог обновляет результат в карточке и сохраняет историю. Подборки используют тот же механизм практики; тренировка дня выбирает задачи по результатам до начала дня, чтобы набор не менялся от каждого нажатия.

В опубликованной версии связи похожих задач рассчитываются заранее по текстовым эмбеддингам. При отсутствии связей есть подбор по номеру и сложности: сайт не требует обращения к внешней языковой модели для каждого ответа.

### Импорт как отдельный конвейер

Рабочий банк не зашит в исходники. Материалы проходят подготовку, проверку файлов и ответов, упаковку с контрольными суммами, пробный импорт и установку. Большие вложения обрабатываются потоком.

У разных источников разные адаптеры; приложение получает собственную структуру задач и блоков. Идентификаторы источника позволяют повторно загружать пакет без дублирования существующих карточек.

**Компромисс:** большой импорт — отдельная операция, а не автоматическая часть `git clone`. Это уменьшает репозиторий и отделяет исходный код от рабочих материалов и данных учеников.

### Отдельный сервис контрольных

Сервис «Инфокод · КР» имеет собственную базу. Он получает задания через API и сохраняет копию для работы. Основная платформа предоставляет интеграцию и подписанный переход преподавателя; её БД не открывается сервису напрямую.

**Граница этого репозитория:** здесь находятся клиент интеграции, API банка и преподавательский экран. Полный код отдельной платформы КР не входит в этот репозиторий.

### Обновление и восстановление

До установки сохраняются данные, медиа и текущий код. Сценарий установки запускается отдельно от SSH-сеанса и пишет результат в журнал. Архивы проверяются по SHA-256; ротация ежедневных копий происходит после успешной проверки новой.

**Компромисс:** копия на том же сервере помогает при неудачном обновлении, но для потери всего VPS требуется отдельное внешнее хранение. Это описано в [инструкции по развёртыванию](../DEPLOYMENT.md).

## Границы результата

Проект показывает полный цикл учебного приложения: модели и права → интерфейсы → данные и интеграции → тесты → развёртывание и обслуживание. Он не заявляет нагрузочные показатели, количество активных пользователей или гарантии защиты от списывания без отдельного измерения.

Код ученика отображается, но не запускается сервером. Тренировочная проверка конечного ответа не заменяет экспертное оценивание развёрнутого решения. Наполнение рабочего сайта зависит от доступных пакетов материалов.
