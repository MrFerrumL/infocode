# Проверки и текущее состояние

[Обзор проекта](../README.md) · [Архитектура](ARCHITECTURE.md)

## Что настроено

Сценарий [`checks.yml`](../.github/workflows/checks.yml) запускает проверки Django и миграций, тесты с SQLite и PostgreSQL, затем сборку и проверку контейнерной конфигурации. Тесты используют отдельную базу.

Команды для локального запуска в активированном окружении:

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test learning --noinput
```

`check_content --strict` предназначен для проверки уже подготовленной базы и медиа. На пустом клоне сначала нужны миграции и наполнение.

## Проверенные опубликованные прогоны

**Проверено 27.10.2026:** [последний опубликованный прогон для `3b7fc12`](https://github.com/MrFerrumL/infocode/actions/runs/40363152984) имеет статус `failure`. Значок в README показывает текущий результат, который может измениться после следующих коммитов.

В изученном ранее [прогоне для `4af6837`](https://github.com/MrFerrumL/infocode/actions/runs/40159282457) упали PostgreSQL-тесты; параллельная задача SQLite была отменена. Это состояние существовало до обновления оформления.

Среди ошибок в журнале прогона `4af6837`:

- Блокировка `FOR UPDATE` затрагивает сторону внешнего соединения, допускающую значения `NULL`, в запросах шагов курса.
- Настройка уровня изоляции при резервировании конфликтует с вложенной или уже начатой тестовой транзакцией.
- Один из сценариев календаря использует название длиннее ограничения поля PostgreSQL.

Исправления нужно проверять на обоих движках: прохождение SQLite само по себе не подтверждает совместимость с PostgreSQL. Изменение оформления не исправляет эти ошибки и не отключает соответствующие тесты.

## Что проверено при оформлении портфолио

- Относительные ссылки, якоря и пути к изображениям в новых документах.
- Целостность 26 изображений галереи и валидность SVG-обложки.
- Отображение README в локальном предпросмотре без горизонтального переполнения.
- Соответствие описанных функций опубликованной версии кода; интеграция с отдельным сервисом КР отмечена явно.

Эта проверка документации не является новым успешным прогоном тестов приложения, нагрузочным испытанием или проверкой рабочей базы.
