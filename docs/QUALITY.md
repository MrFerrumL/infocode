## Что настроено

Сценарий [`checks.yml`](../.github/workflows/checks.yml) запускает проверки Django и миграций, тесты с SQLite и PostgreSQL, затем сборку и проверку контейнерной конфигурации. Тесты используют отдельную базу.

Команды для локального запуска в активированном окружении:

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test learning --noinput
```

`check_content --strict` предназначен для проверки уже подготовленной базы и медиа. На пустом клоне сначала нужны миграции и наполнение.

## Устранённые проблемы PostgreSQL и HTTP

В [историческом прогоне `4af6837`](https://github.com/MrFerrumL/infocode/actions/runs/40159282457) PostgreSQL-тесты падали, а параллельная задача SQLite отменялась. Проверка 2 ноября устранила выявленные причины:

- Редактор и перестановка шагов блокируют только изменяемые строки, без недопустимой блокировки nullable-стороны соединения.
- Проверки резервирования выполняются вне внешней тестовой транзакции. Рабочая гарантия `REPEATABLE READ READ ONLY` сохранена и проверяется отдельно.
- Потоковые ответы в тестах закрываются через обёртку тестового клиента, без преждевременного закрытия PostgreSQL-соединения.
- Длинная строка в проверке календаря укладывается в ограничение поля, сохраняя проверку переноса строк UTF-8.
- HEAD не возвращает тело страницы, которое могло нарушать постоянное соединение прокси.
- В матрице GitHub Actions отключена досрочная отмена второй БД при ошибке первой; сами тесты не отключены.

Причина кратковременной недоступности до обращения не доказана журналами сервера. Отдельно воспроизведён разрыв TLS через локальный VPN-маршрут при исправном прямом HTTPS-подключении. Правки приложения не заменяют настройку маршрута VPN.

Сценарий выпуска, проверки доступности и границы автоматического восстановления описаны в [инструкции эксплуатации](OPERATIONS.md).
