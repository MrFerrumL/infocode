# Инфокод — техническое руководство

Учебная платформа для подготовки к ЕГЭ по **информатике и физике**: каталог задач с проверкой на странице, подборки, варианты, курсы, конспекты, домашние задания, расписание и кабинет преподавателя.

Серверная часть — Python/Django; интерфейс — HTML, CSS и JavaScript. Локально используется SQLite, на сервере — PostgreSQL, Docker Compose, Waitress и Caddy с HTTPS. Node.js для работы платформы не требуется.

Обзор проекта со скриншотами — в [README.md](README.md). **Руководство сверено с исходниками 21 октября 2026 года.** Здесь собраны изменения после первоначального запуска, включая дополнения из ветки `kompege-numbers-11-15`. Клонирование GitHub переносит код, но не рабочую базу, пользователей, результаты и загруженные файлы. Наличие функции импорта не означает, что соответствующий банк уже установлен в конкретной базе.

## Локальный запуск

Рекомендуется Python 3.12; скрипт запуска рассчитан на Python 3.10–3.13. Из папки с `manage.py`:

```powershell
python start_local.py
```

Если Windows не находит `python`, используйте `py start_local.py`. В PyCharm откройте папку проекта и **View → Tool Windows → Terminal**. Bash для локального запуска в Windows не нужен.

При первом запуске скрипт создаёт `.venv`, устанавливает зависимости, применяет миграции, добавляет демонстрационные материалы и собирает статику. Интернет нужен для установки пакетов. Откройте **http://127.0.0.1:8000/**.

Если активного администратора ещё нет, создаётся `admin` со случайным паролем: доступ выводится в терминал и сохраняется в `.local-credentials.txt`, исключённом из Git. При повторном запуске существующие пользователи и результаты сохраняются. Остановка — Ctrl+C. Порт 8000 должен быть свободен.

`127.0.0.1` доступен только на вашем компьютере; ученикам с других устройств нужен сервер. Команды Linux из серверной инструкции выполняются после подключения по SSH к Ubuntu, а не непосредственно в локальном PowerShell.

### Ручной запуск без демоданных

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py init_platform
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py collectstatic --noinput
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

`init_platform` создаёт только 27 разделов информатики, без задач, курсов и аккаунтов. На Linux интерпретатор окружения находится в `.venv/bin/python`. Для производства используется конфигурация Docker ниже, а не `runserver`.

## Предметы и учётные записи

Верхний переключатель **«Информатика | Физика»** запоминает выбор в сессии и по возможности оставляет пользователя в том же разделе.

| Общие данные | Раздельные по предметам |
|---|---|
| Пользователи, преподаватели и ученики | Темы и каталог: 27 номеров информатики, 26 физики |
| Группы и приглашения | Подборки, варианты и КР по темам |
| Расписание, назначения и уведомления | Курсы, конспекты и пройденные номера |
| Учётные данные | Подбор задач тренировки дня |

Предметный контекст реализован в `learning/subjects.py`: middleware устанавливает его для запроса, стандартные менеджеры фильтруют модели по предмету. В служебных командах по умолчанию используется информатика; `using('phys')` переключает на физику. Для намеренной работы со всеми предметами предусмотрены менеджеры `all_objects`.

Преподаватель открывает **Ученики → Создать ученика**, вводит имя и фамилию, при необходимости выбирает группу. Логин создаётся из имени латиницей, при совпадении получает номер; пароль генерируется автоматически. Карточку доступа можно скопировать и передать ученику. Забытый пароль заменяется через **«Выдать новый пароль»**, история обучения сохраняется.

В базе хранятся хеши паролей, посмотреть прежний пароль нельзя. Текущая конфигурация допускает простые пользовательские пароли и не требует обязательной смены выданного пароля при первом входе. Самостоятельная регистрация работает отдельно; для прикрепления к преподавателю удобно использовать приглашение в группу. Инструкция — [STUDENTS.md](STUDENTS.md).

## Каталог задач

### Условия и ответы на одной странице

Выбор номера открывает список карточек с полными условиями. Ввод, проверка и история ответа находятся в самой карточке; открывать отдельную страницу задания не требуется. Большие разделы разбиты на страницы.

- Поиск по названию, тексту и ID; фильтры номера, сложности, статуса решения, типа и сайта-источника.
- Пять уровней: простой, средний, сложный, ЕГЭ и гроб.
- Файлы данных и ссылка на оригинал из условия.
- Проверка короткого ответа на сервере, история попыток, избранное и работа над ошибками.
- Разбор после попытки; в экзамене — после сдачи с учётом настроек варианта.
- Обновление ответа без перехода со страницы; предусмотрена обычная серверная отправка формы без JavaScript.
- Увеличение условия в просмотрщике, оформление для светлой и тёмной темы.
- Компактные шапки и уменьшенные промежутки между условием и ответом во всех карточках.

Условия источников сохраняются снимками шириной **1920 px**, без переписывания через OCR. Сохраняются таблицы, формулы, код и отступы. При этом снимок не может восстановить детали уже нечёткой исходной иллюстрации.

### Источники и порядок

ID источника хранится отдельно от внутреннего ID задачи. Над условием отображается пометка источника: демоверсия, реальный ЕГЭ, пробник/ЕГКР или авторская задача. Фильтр сайтов показывает банки, реально присутствующие в базе.

Порядок по умолчанию: КЕГЭ от новых к старым, Поляков по авторской нумерации с первых, собственные задачи после импортированных. Дополнительно есть сортировки с первой/последней задачи и по сложности.

Номер категории старого каталога источника может отличаться от номера в конкретном КИМ. Импорт вариантов отдельно сохраняет порядок КИМ; его нельзя определять только по категории общего банка.

### Связанные задания 19–21

В информатике связанные вопросы КЕГЭ и Полякова объединяются в одну карточку с общим условием и тремя полями. У каждого вопроса отдельная проверка, история и прогресс. Ошибка или поиск по вопросу 20/21 приводит к его группе. Статистика остаётся раздельной; генератор вариантов берёт связанные вопросы из одной группы. Задачи без связанной группы остаются самостоятельными.

### Редактор банка

Преподаватель составляет условие и разбор из заголовков, текста, изображений, файлов и Python-кода в произвольном порядке. Текст необязателен. Код хранится с отступами и не запускается. Можно копировать карточки и блоки, оставлять черновики, публиковать, массово обрабатывать, перемещать в корзину и восстанавливать.

Выданные работы сохраняют снимки материалов. Вложения выдаются защищёнными обработчиками; материалы разбора закрыты до предусмотренного момента. Детали — [ADMIN_GUIDE.md](ADMIN_GUIDE.md).

## Подборки и рекомендации

### Подборки

Раздел организован по номерам. Собственные подборки информатики — «знакомство», «на подумать», «повторение», по умолчанию по 10 задач. Повторение использует пометки реальных экзаменов, демоверсий и ЕГКР. На странице набора работают ответы, история, разборы, групповые задачи 19–21 и прогресс ученика.

Есть **73 ссылки на подборки Яндекс Учебника**. До переноса подборка открывается на стороне Яндекса. Для материалов, которые преподаватель сохранил самостоятельно и имеет право использовать, предусмотрен импорт папки/ZIP с картинками условий, файлами и `ответы.txt`. Импортированный набор решается на платформе; импортёр не копирует автоматически весь банк Яндекса.

```bash
python manage.py sync_collections
python manage.py sync_collections --size 15
python manage.py import_yandex_collections PATH_TO_COLLECTIONS --dry-run
python manage.py import_yandex_collections PATH_TO_COLLECTIONS
```

Повторный импорт Яндекса обновляет те же задачи, сохраняя результаты. Форматы папок — [COLLECTIONS.md](COLLECTIONS.md).

### Похожие задачи

Кнопка **«≈ Похожие»** раскрывает до пяти задач того же номера, доступных для решения на месте. Приоритет получают ещё не решённые задачи.

Текстовые связи КЕГЭ и Полякова заранее рассчитываются моделью `intfloat/multilingual-e5-small`, затем загружаются в базу. Нейросеть не запускается при каждом ответе ученика. Для задач без подходящих связей используется подбор по номеру и сложности.

```bash
python deploy/build_similar_tasks.py WORK learning/data/similar_tasks.json.gz
python manage.py sync_similar_tasks
```

Генератор индекса — отдельный инструмент подготовки со своими ML-зависимостями; они не нужны для обычной работы веб-приложения. Подробнее — [IMPORT_POLYAKOV.md](IMPORT_POLYAKOV.md).

### Тренировка дня

Набор содержит **до 8 задач текущего предмета**, если хватает подходящих нерешённых задач. Основа — результаты до начала дня, поэтому набор остаётся стабильным в течение дня:

1. Похожие на последние ошибки задачи.
2. Слабые номера: минимум три ответа за 90 дней и менее 80% правильных.
3. Простые задачи по новым номерам.
4. Дополнение нерешёнными задачами для повторения.

Рядом видна причина выбора. Решённые до начала дня задачи повторно не предлагаются; вопросы 20/21 входят в общую карточку 19–21.

## Варианты, контрольные и ДЗ

### Конструктор и назначения

Варианты собираются случайно по номерам или вручную по ID; можно настроить количество задач, сложность, время и режим кода. Контрольные по темам используют тот же механизм в отдельном разделе.

Назначение работы: содержание → ученики и сроки → правила и отправка. Можно выбрать готовый вариант, сгенерированный набор или конкретные ID, назначить группе/ученикам, ограничить попытки и срок. Есть журнал, уведомления о сдаче, CSV и печать условий/ключей.

### Экзаменационная станция

Увеличенное условие, навигация по номерам, счётчик сохранённых ответов, таймер и файлы. Составные ответы вводятся в ячейки и строки; вставка нескольких чисел раскладывается по полям. Есть очистка и сохранение ответа.

Время учитывается сервером: закрытие страницы не останавливает таймер. Просроченные попытки завершаются обслуживающей командой. Результат показывает ответы и разрешённые ключи. Для информатики реализованы правила тренировочного режима КЕГЭ: №1–25 по одному первичному баллу, №26–27 до двух с предусмотренным частичным зачётом, перевод в тестовые баллы.

По отчёту подготовки архива — **145 вариантов** за 2024/25, 2025/26 и 2026/27 учебные годы. Задачи только из вариантов могут быть скрыты из каталога (`in_catalog=False`), статистики каталога и случайной генерации. Особенности скрытых автором ответов и недоступных материалов источника описаны в [VARIANTS_KOMPEGE.md](VARIANTS_KOMPEGE.md).

### Домашние задания

ДЗ можно проходить повторно даже после зачёта. Новая попытка начинается с пустых ответов; ответы, код и комментарии к задачам сохраняются отдельно. Преподаватель видит историю, лучший и последний результат. Повторы по умолчанию не ограничены, при необходимости задаётся лимит. Поддерживаются ручная проверка, файлы и возврат на доработку. См. [HOMEWORK.md](HOMEWORK.md).

### Python в ответах

Режим задачи/слайда: без кода, необязательный или обязательный код. Ученик вводит программу либо импортирует `.py`; преподаватель видит её в истории и результатах. **Пользовательский код не исполняется и автоматически не оценивается**. Автоматическая проверка относится к обычному ответу задачи.

## Курсы и конспекты

### Курсы

Структура: **курс → раздел → урок → шаг/слайд**. Можно сочетать теорию, фото, видео, конспект, тест и практику, задавать порядок, баллы и лимиты.

- Визуальные блоки текста с форматированием, изображений, MP4/WebM, Python, файлов и разделителей.
- Перестановка, вставка, копирование, удаление и изображения из буфера.
- Один/несколько правильных вариантов, короткий или числовой ответ с погрешностью, пропуски, сопоставление.
- Копирование шагов, уроков, разделов и курсов в черновики без ответов учеников.
- Предпросмотр, серверный черновик, восстановление и защита от конфликтов двух вкладок.
- Учебный экран с программой, записью, продолжением, прогрессом, историей и обсуждениями с модерацией.
- Видеоплеер: перемотка, полный экран, сохранение позиции, выдача HTTP Range.

Доступ определяется публикацией, группой и правилами курса. Изменение содержания создаёт новую версию; старая история остаётся, актуальное прохождение может потребовать повторного ответа. Новые локальные файлы отправляются при полном сохранении, а не вместе с текстовым черновиком.

### Конспекты с ячейками

Библиотека поддерживает текст, код, фото, видео, файлы и разделители, поиск, оглавление, черновики, предпросмотр, печать/PDF и подключение к курсам. В обычном редакторе — до 40 ячеек.

Один конспект используется в нескольких уроках. При изменении обновляются связанные материалы; при снятии публикации или переносе в корзину связанные слайды становятся черновиками. Внутри курса доступ определяется курсом, в библиотеке — публикацией и группой конспекта.

### Colab / Jupyter

Скачайте `.ipynb` в Colab и откройте **Конспекты → Загрузить из Colab (.ipynb)**. Лимит — 60 МБ. Сохраняются Markdown, таблицы, сворачиваемые условия, изображения, код и поддерживаемый сохранённый вывод. Это просмотр готового документа, а не работающее ядро Colab.

Блокноты длиннее 40 ячеек обновляются через **«Обновить из Colab»**; редактор оставляет настройки названия, доступа и публикации.

```bash
python manage.py import_ipynb notebook.ipynb --owner TEACHER_LOGIN --publish
```

Одинаковые владелец и название означают обновление существующего конспекта. В Git добавлен исходный [`colab/ege24_polyakov_1-250.ipynb`](colab/ege24_polyakov_1-250.ipynb): **1786 ячеек**, из них 1115 Markdown и 671 кода. Он не загружается в базу автоматически:

```bash
python manage.py import_ipynb colab/ege24_polyakov_1-250.ipynb --owner TEACHER_LOGIN --publish
```

Публикация, права, подключение и обновление — [NOTEBOOKS.md](NOTEBOOKS.md).

## Кабинет преподавателя

Главная показывает очередь проверки, ближайшие сроки, черновики курсов и учеников с просроченными незачтёнными работами. Есть карточки учеников, заметки, активность, слабые темы, журнал, отчёты CSV, медиатека, импорт CSV, дубликаты, корзина, история изменений и проверка готовности.

### Пройденные номера

Таблица: строки — группы, столбцы — введение и номера текущего предмета. Преподаватель отмечает пройденное, жёлтым выделяет повторение, красным — проблемные темы. Цвет и отметка независимы. Ученики видят таблицу групп своего преподавателя только для чтения; своя группа выделяется. Отметки информатики и физики раздельные.

### Расписание

Месяц, неделя, день и список; время, участники, повторения, цвета, ссылки на встречу, напоминания. Можно сделать занятие общим для всех учеников, перенести/отменить одно повторение, создать приватное событие, экспортировать `.ics`. Месячный вид показывает все занятия дня.

Ученики видят доступные занятия и сроки ДЗ/КР. Время московское, напоминания внутри платформы. Экспорт `.ics` не является двусторонней синхронизацией Google Calendar. См. [SCHEDULE.md](SCHEDULE.md).

## Оформление

Светлая/тёмная тема, боковое меню, мобильная навигация и представление ученика для преподавателя. Условия и просмотрщик адаптируются к теме.

Верхняя кнопка сезона позволяет выбрать Хеллоуин, зиму, Новый год или отключить украшения. Личный выбор хранится в браузере. Настройка по умолчанию в `.env.production`:

| `SITE_SEASON` | Поведение |
|---|---|
| `auto` | 15.10–02.11 Хеллоуин; 03.11–30.11 и 15.01–конец февраля зима; 01.12–14.01 Новый год |
| `halloween`, `winter`, `newyear` | Выбранный сезон независимо от календаря |
| `none` | Без украшений по умолчанию |

На экзаменационной станции и при предпочтении уменьшенного движения анимации нет.

## Наполнение и импорт

### Что хранится в репозитории

Код, миграции, тесты, инструкции, собственный банк физики, список ссылок подборок, индекс похожести и указанный блокнот Colab. **Рабочая БД, `uploads/`, ученики и результаты, большие пакеты ZIP, секреты и резервные копии исключены из Git.**

`seed_demo` добавляет вводное наполнение информатики: 81 авторскую задачу, текстовые учебные материалы и демонстрационные работы. Это примеры функций, а не полный официальный банк или гарантия соответствия каждого примера актуальному КИМ. Готовые видеокурсы не поставляются.

### КЕГЭ

Перенос выполняется по подтверждённому пользователем разрешению. Следующие количества относятся к отчётам снимка **17.10.2026**, а не к постоянно обновляющемуся сайту источника:

| Категории | Задач по номерам | Файлы и особенности |
|---|---|---|
| 1–5 | 239 / 230 / 223 / 229 / 292 | Первые полные пакеты |
| 6–10 | 228 / 306 / 344 / 217 / 174 | 231 файл |
| 11–15 | 245 / 66 / 283 / 314 / 272 | Без файлов данных |
| 16–18 | 255 / 231 / 228 | 464 файла |
| 19–21 | 239 групп = 717 вопросов | Общее условие и отдельные вопросы |
| 22–27 | 208 / 68 / 308 / 306 / 235 / 119 | 1143 файла; большие данные №24 |

Процесс: исходные данные → проверка условий/ответов/файлов → снимки страниц в браузере → упаковка → предварительная проверка → импорт. Метаданные и SHA-256 сохраняются в пакете. Для крупных данных используется потоковая обработка; текущие лимиты — 50 МБ на файл задачи и 3 ГБ на пакет.

```bash
python manage.py import_kompege_numbers PATH_TO_BUNDLE.zip --numbers 6 7 8 9 10 --dry-run
python manage.py import_kompege_numbers PATH_TO_BUNDLE.zip --numbers 6 7 8 9 10 --publish
python manage.py import_kompege_variants PATH_TO_VARIANTS.zip --dry-run
python manage.py import_kompege_variants PATH_TO_VARIANTS.zip --publish
```

Обычный повторный импорт пропускает уже существующие карточки, сохраняя правки и результаты. Режим замены имеет отдельные ограничения и для обычного пополнения не требуется. Проверенное восстановление ответа №7/31372 с привязкой к хешам описано в отчёте №6–10.

Подробные отчёты и команды — в документах `IMPORT_KOMPEGE_NUMBERS*.md` и [VARIANTS_KOMPEGE.md](VARIANTS_KOMPEGE.md).

### К. Поляков

Поддержана подготовка сборника №1–25: условия из DOC/PDF, ответы из таблицы, файлы из архивов, ссылки на видео. Сохраняется авторская нумерация, дополнительные разделы №7 и игры 19–21. При подготовке исключаются совпадения с КЕГЭ по содержанию и ответу. Повторный импорт пропускает загруженное.

Для подготовки документов используется LibreOffice и отдельные инструменты обработки PDF; обычному веб-приложению они не нужны. См. [IMPORT_POLYAKOV.md](IMPORT_POLYAKOV.md).

### Физика

В `learning/data/physics/` поставляются **217 собственных задач по 26 номерам**, изображения и шесть конспектов. Текущий банк даёт **36 подборок** по доступным уровням и три тренировочных варианта; не каждый номер представлен всеми уровнями.

```bash
python manage.py seed_physics
```

Команда создаёт/обновляет встроенные материалы по ID, сохраняя ответы учеников. Содержимое задач и конспектов обновляется из поставляемых файлов; вручную изменённые встроенные материалы перед повторным наполнением следует сохранить отдельно. Для конспектов и вариантов нужен активный администратор. Вариант с уже имеющимися попытками не пересоздаётся.

Реализован тренировочный формат физики 2026: 26 заданий, 235 минут, до 45 первичных баллов, отдельные правила частичного зачёта и шкала. В развёрнутой части проверяется конечный ответ, а не полное письменное решение. Подробнее — [PHYSICS.md](PHYSICS.md).

## Сервер и обновления

### Первая установка

Пошагово — [FIRST_LAUNCH.md](FIRST_LAUNCH.md) и [DEPLOYMENT.md](DEPLOYMENT.md). Нужны VPS/Ubuntu, домен с A-записью на IP сервера, SSH и Docker Engine/Compose.

Из папки проекта **на новом сервере**:

```bash
python3 deploy/configure.py --domain YOUR_DOMAIN --email YOUR_EMAIL
docker compose --env-file .env.production -f compose.production.yaml build
docker compose --env-file .env.production -f compose.production.yaml up -d db migrate
docker compose --env-file .env.production -f compose.production.yaml run --rm --no-deps web python manage.py init_platform
docker compose --env-file .env.production -f compose.production.yaml run --rm --no-deps web python manage.py createsuperuser
docker compose --env-file .env.production -f compose.production.yaml up -d
```

`configure.py` создаёт индивидуальные секреты и не перезаписывает существующий `.env.production`. На работающем сайте не генерируйте настройки заново. Перенос существующих пользователей делается восстановлением в пустую среду, а не повторным созданием аккаунтов.

### Производственная конфигурация

| Сервис | Назначение |
|---|---|
| `db` | PostgreSQL 16 и постоянный том `pgdata` |
| `migrate` | Применение миграций до запуска приложения |
| `web` | Django/Waitress и проверка работоспособности |
| `maintenance` | Просроченные попытки, напоминания, ежедневные копии |
| `caddy` | HTTPS и обратный прокси, публичные 80/443 |

Приложение и БД не публикуют свои порты наружу. Медиа, журналы, копии и сертификаты сохраняются в томах. Используйте `compose.production.yaml`; обычный `compose.yaml` — другая конфигурация.

Основные настройки: `SECRET_KEY`, `DB_PASSWORD`, `APP_DOMAIN`, `ACME_EMAIL`. Дополнительные: `SITE_OWNER_NAME`, `SITE_CONTACT_EMAIL`, `SITE_CONTACT_TELEGRAM`, `GOOGLE_SITE_VERIFICATION`, `SITE_SEASON`. Пустые контакты на публичной странице не показываются.

### Обновление существующего VPS

1. Сделать и проверить копию базы/медиа, отдельно сохранить код и секреты.
2. Получить новый код из GitHub или загрузить свежий архив исходников.
3. Пересобрать образ, применить миграции, импортировать нужные проверенные материалы.
4. Запустить сервисы, проверить содержимое и `/health/`.

`deploy/install_kompege_pilot.py`, несмотря на историческое имя, поддерживает разные обновления:

```powershell
python deploy/install_kompege_pilot.py --categories PATH_TO_BUNDLE.zip --numbers 6 7 8 9 10
python deploy/install_kompege_pilot.py --variants PATH_TO_VARIANTS.zip
python deploy/install_kompege_pilot.py --polyakov PATH_TO_POLYAKOV_BUNDLE.zip
python deploy/install_kompege_pilot.py --notebooks colab/ege24_polyakov_1-250.ipynb
python deploy/install_kompege_pilot.py --physics
```

Проверьте `--help` перед запуском. По умолчанию нужны соседние `../infocode-python.zip` и `../kompege-pilot-135.zip`, SSH-ключ и настроенное назначение. Параметры `--source`, `--bundle`, `--host`, `--user`, `--key`, `--domain` позволяют их переопределить. Клон Git не создаёт ZIP-пакеты; архив исходников должен соответствовать обновляемому коду.

Установщик делает предварительную копию данных/медиа/кода, сохраняет `.env.production`, запускает сценарий через `nohup`/`setsid` и следит за журналом с кодом завершения. Обрыв SSH не останавливает уже запущенный сценарий; перед повтором нужно проверить первый журнал. Хранятся три новейшие установочные копии каждого вида.

```bash
docker compose --env-file .env.production -f compose.production.yaml ps
docker compose --env-file .env.production -f compose.production.yaml exec -T web python manage.py check_content --strict
docker compose --env-file .env.production -f compose.production.yaml logs --tail=80 web caddy maintenance
```

**Push в GitHub не обновляет VPS автоматически** — развёртывание выполняется отдельно. Публичная главная, контакты и `robots.txt` описаны в [PUBLIC_PAGES.md](PUBLIC_PAGES.md). HTTPS не гарантирует снятия репутационного предупреждения браузера: решение принимает соответствующий сервис проверки.

## Резервные копии

Переносимый архив включает данные, пользователей и медиа с манифестом SHA-256. Существующая копия не перезаписывается, целостность проверяется после создания.

```bash
python manage.py backup_platform backups/manual-copy.zip
python manage.py backup_platform backups/manual-copy.zip --verify
```

На VPS:

```bash
docker compose --env-file .env.production -f compose.production.yaml exec -T web python manage.py backup_platform /backups/manual-copy.zip
```

`maintenance` создаёт ежедневные копии и хранит три последние. Ротация происходит только после успешной проверки текущего архива. Установочные копии имеют отдельную ротацию.

Восстановление допускается в **пустую БД и пустую папку медиа**, согласно [DEPLOYMENT.md](DEPLOYMENT.md):

```bash
python manage.py restore_platform PATH_TO_BACKUP.zip
```

Исходники и `.env.production` сохраняйте отдельно. Архивы содержат сведения об учениках и не публикуются в GitHub. Для восстановления после потери VPS нужна также копия за пределами этого сервера.

## Проверки и ограничения

Из окружения с установленными зависимостями:

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test learning --noinput
python manage.py check_content --strict
```

`check_content` проверяет текущую БД и ссылки на медиа без изменения данных. На новом клоне перед ним нужны миграции и наполнение. Число тестов растёт; результаты старых отчётов относятся к своему этапу, а не автоматически к последней версии.

Тесты охватывают каталог и ответы, импорт/повторную загрузку, игры, варианты, предметную изоляцию, тренировку дня, пройденные номера, расписание, Colab, курсы, роли, файлы, резервирование и установщик.

Проверка перед обновлением `main` от **21.10.2026**: **381 тест успешно пройден** в локальном окружении Windows/Python 3.13 с отдельной тестовой БД SQLite. `manage.py check` не обнаружил проблем; `makemigrations --check --dry-run` подтвердил отсутствие несохранённых изменений схемы. Проверены относительные ссылки руководства, якоря оглавления и формат JSON блокнота. Рабочая БД при тестировании не использовалась. Проверки PostgreSQL и контейнеров отдельно предусмотрены в `.github/workflows/checks.yml`; локальный результат не заменяет их.

Текущие ограничения:

- Нет исполнения пользовательского Python, автопроверки программ тестами и работающего ядра Jupyter.
- Нет прокторинга или блокировки сторонних ресурсов во время работы.
- Конечный ответ физики не заменяет экспертную оценку развёрнутого решения.
- Напоминания внутренние; двусторонней синхронизации Google Calendar нет.
- Внешние банки/медиа не включены в Git и не появляются после одного клонирования.
- Тесты приложения не являются нагрузочной проверкой VPS или подтверждением решений Google о домене.

Защита включает хеширование паролей Django, CSRF, серверные проверки ролей/владельцев, защищённые файлы, ограничения загрузок и нейтрализацию формул в CSV. Рабочее окружение требует корректного HTTPS, секретов и доверенного прокси. `.env`, SSH-ключи, БД и доступы учеников исключены из Git.
