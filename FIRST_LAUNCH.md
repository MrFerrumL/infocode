# Первый запуск пустой платформы на HSVDS

Эта инструкция — для выбранного VPS с Ubuntu 24.04, IP `195.209.211.242` и пользователем `ubuntu`. Сначала запускаем пустую платформу с разделами № 1–27; свои задания, картинки и курсы преподаватель добавляет после входа. Локальная база, демонстрационные задания и аккаунты с компьютера не переносятся.

Для установки используйте обновлённый архив `infocode-python.zip` рядом с папкой проекта. Здесь выбран один способ загрузки — архивом. Настройка доступа VPS к приватному GitHub для этого не требуется. Отправка коммита в GitHub сама по себе не обновляет установленный сайт.

## 1. Домен

Зарегистрируйте свободный домен латиницей в зоне `.ru`, например через [Beget](https://beget.com/ru/domains). На странице 15 октября 2026 указаны 199 ₽ за регистрацию на первый год и 420 ₽ за продление на год; итог проверьте при заказе. Укажите собственные данные администратора домена и действующую почту.

Для этой установки достаточно домена с DNS-управлением. Сервер уже арендован у HSVDS. Если при регистрации предлагается привязка к сайту Beget, выберите «Не прилинковывать домен»; сайт будет работать на VPS. [Инструкция регистратора](https://beget.com/ru/kb/manual/domeny-i-poddomeny).

## 2. DNS: направить домен на сервер

В панели Beget откройте DNS-записи купленного домена. Оставьте DNS-серверы Beget, если домен использует их: для подключения внешнего VPS меняется A-запись.

| Поле | Значение |
|---|---|
| Домен / имя | Основной купленный домен; в поле поддомена обычно `@` или пустая строка по подсказке панели |
| Тип | `A` |
| IP-адрес | `195.209.211.242` |
| TTL | По умолчанию |

Если A-запись для основного домена уже указывает на другой IP, замените её значение. Для основного адреса не оставляйте одновременно старый и новый IP. Не меняйте записи почты MX/TXT. AAAA добавляется только при настроенном IPv6; чужая AAAA для этого имени не должна остаться. Адрес `www` в этой инструкции не используется.

Сохраните запись. [Справка Beget по DNS](https://beget.com/ru/kb/manual/dns).

В **PowerShell на компьютере** проверьте результат:

```powershell
$siteDomain = Read-Host "Купленный домен без https://"
Resolve-DnsName $siteDomain -Type A
```

Ожидаемый IPv4: `195.209.211.242`. Обновление DNS не всегда происходит сразу. Само изменение DNS ещё не запускает приложение — для этого нужны следующие шаги.

## 3. Доступ к серверу

В панели HSVDS дождитесь статуса «Включён» и проверьте баланс. Скачайте ключ `.PEM` из раздела подключения в папку «Загрузки». В примере имя ключа со скриншота; если браузер изменил имя, поправьте команду.

**PowerShell на компьютере:**

```powershell
ssh -i "$env:USERPROFILE\Downloads\privatekey-1152809.pem" ubuntu@195.209.211.242
```

При первом подключении SSH попросит подтвердить ключ сервера; сверьте отпечаток через консоль или поддержку провайдера. Не отправляйте приватный `.PEM` в чат или GitHub.

**После подключения, в терминале сервера:**

```bash
sudo -i
```

Далее Linux-команды выполняются в этом окне от root. После повторного входа по SSH снова нужны `sudo -i` и `cd /opt/infocode`, если работаете с проектом. [Справка HSVDS](https://hsvds.ru/faq/).

## 4. Docker и порты

Если удобнее работать из Windows, выполните **в PowerShell на компьютере** одну команду:

```powershell
& "C:\Users\tgpro\Documents\Codex\2026-09-28\yf\outputs\infocode\.venv\Scripts\python.exe" "C:\Users\tgpro\Documents\Codex\2026-09-28\yf\outputs\infocode\deploy\setup_server.py"
```

Нужны уже скачанный ключ `Downloads/privatekey-1152809.pem` и подтверждённый при первом входе SSH-ключ сервера. Скрипт сначала проверяет синтаксис команд через Bash на VPS, затем проверяет Ubuntu 24.04, устанавливает Docker из официального репозитория, разрешает SSH/HTTP/HTTPS и проверяет запуск Docker. Перед включением UFW разрешается порт SSH 22. Команды Linux выполняются на сервере. Ключ доступа не копируется и не изменяется.

Дождитесь строки `INFOCODE_SERVER_READY` и сообщения `Server preparation finished`. Возврат к приглашению PowerShell после завершения нормален. При ошибке сохраните вывод: последующие шаги автоматически не запускаются. После успешной подготовки переходите к шагу 5. Скрипт пока не загружает сайт и не создаёт пользователей.

Для других реквизитов поддерживаются `--host`, `--user` и `--key`. Уже установленные Docker и Compose повторно не устанавливаются. Ниже приведены ручные команды для того же этапа; после успешного запуска скрипта повторять их не требуется.

**На сервере:**

```bash
apt-get update
apt-get install -y ca-certificates curl python3 unzip ufw
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc
```

Следующий блок вставьте целиком, включая последнюю строку `EOF`:

```bash
cat > /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: noble
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
```

```bash
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
systemctl enable --now docker
docker compose version
```

Должна появиться версия Docker Compose. Команды соответствуют [установке Docker для Ubuntu](https://docs.docker.com/engine/install/ubuntu/).

Разрешите SSH перед включением firewall:

```bash
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 443/udp
ufw enable
```

Подтвердите `y`. Если у провайдера включён отдельный сетевой firewall, разрешите TCP 22/80/443 и UDP 443 также в его панели. В конфигурации проекта наружу публикуются только 80/443, PostgreSQL и приложение остаются во внутренней сети Docker.

## 5. Загрузить готовый код

Откройте **второе окно PowerShell на компьютере**, оставив SSH-подключение открытым:

```powershell
scp -i "$env:USERPROFILE\Downloads\privatekey-1152809.pem" "C:\Users\tgpro\Documents\Codex\2026-09-28\yf\outputs\infocode-python.zip" ubuntu@195.209.211.242:/home/ubuntu/infocode-python.zip
```

После успешной загрузки вернитесь в **терминал сервера**:

```bash
mkdir -p /opt
unzip /home/ubuntu/infocode-python.zip -d /opt
cd /opt/infocode
```

Этот шаг рассчитан на первый запуск. Если `/opt/infocode` уже существует и unzip спрашивает о замене файлов, не заменяйте рабочую установку по инструкции первого запуска: обновление описано в [DEPLOYMENT.md](DEPLOYMENT.md). Архив содержит код и документацию, без `.venv`, базы, загруженных материалов и секретов.

## 6. Создать настройки и подготовить базу

К этому моменту проверка DNS из шага 2 должна возвращать IP сервера.

**На сервере, в `/opt/infocode`:**

```bash
python3 deploy/configure.py
```

Введите:

- `Domain:` — купленный домен без `https://`, `www` и `/`.
- `Email:` — действующую собственную почту для сертификата. Вводите адрес в английской раскладке: кириллические символы, даже похожие на латинские, вызывают ошибку `contact email contains non-ASCII characters` при выпуске сертификата. Установщик проверяет это до создания секретов.

Скрипт создаёт `.env.production` с уникальными секретами. Уже существующий файл не перезаписывает. Этот файл нужен для восстановления и хранится приватно вне GitHub.

```bash
docker compose --env-file .env.production -f compose.production.yaml build
docker compose --env-file .env.production -f compose.production.yaml up -d db
docker compose --env-file .env.production -f compose.production.yaml run --rm migrate
```

После ошибки любой из команд остановитесь и сохраните её вывод; не продолжайте последующие шаги вслепую.

## 7. Пустой каталог и собственный администратор

```bash
docker compose --env-file .env.production -f compose.production.yaml run --rm --no-deps web python manage.py init_platform
docker compose --env-file .env.production -f compose.production.yaml run --rm --no-deps web python manage.py createsuperuser
```

Первая команда создаёт только разделы № 1–27. Повторный запуск не меняет существующие названия, описания и задачи. Вторая предлагает выбрать логин, почту и пароль администратора. При вводе пароля символы в терминале не отображаются — это нормально. На сервере будут действовать введённые здесь реквизиты; локальный пароль с компьютера не переносится.

Не запускайте `seed_demo` или `start_local.py` на VPS, если хотите наполнять платформу своими материалами. Не запускайте `restore_platform`: перенос локальной базы в этом сценарии не нужен.

## 8. Запуск и проверка

```bash
docker compose --env-file .env.production -f compose.production.yaml up -d
docker compose --env-file .env.production -f compose.production.yaml ps -a
```

Откройте свой адрес `https://КУПЛЕННЫЙ-ДОМЕН/health/`. Ожидаемый ответ: `{"status": "ok"}`. Затем откройте `https://КУПЛЕННЫЙ-ДОМЕН/login/` и войдите новым администратором.

HTTPS-сертификат выпускает и продлевает Caddy. Условия: DNS направлен на VPS, порты 80/443 доступны. [Автоматический HTTPS Caddy](https://caddyserver.com/docs/automatic-https).

В списке контейнеров `migrate` со статусом `Exited (0)` — норма. При проблеме проверьте:

```bash
docker compose --env-file .env.production -f compose.production.yaml logs --tail=80 web caddy maintenance
docker compose --env-file .env.production -f compose.production.yaml exec web python manage.py check_content --strict
```

Пустой банк до добавления задач ожидаем. Сайт работает при выключенном компьютере и закрытом окне SSH.

## 9. Наполнение и ученики

1. Откройте «Кабинет преподавателя → Банк заданий → Добавить задание» (`/teacher/tasks/new/`).
2. Выберите номер 1–27, сложность, название и правильный ответ. Добавьте текст или фото условия, файлы и разбор. Сохраните черновик либо опубликуйте готовую задачу.
3. Проверьте одно задание с отдельного ученического аккаунта, включая фото и скачивание файлов. После проверки добавляйте остальной банк.
4. Создайте курс и его разделы. Материалы и уроки можно заполнять постепенно; ученикам показываются опубликованные элементы с соответствующим доступом.
5. Через «Ученики → Создать ученика» выдайте аккаунты либо создайте приглашение в группу. Подробности — [STUDENTS.md](STUDENTS.md).
6. Создайте ДЗ, КР и занятия в расписании. Отправляйте ученикам адрес домена, а не `127.0.0.1`.

Добавление задач и уроков через сайт не требует редактирования исходников или нового push в GitHub. После публикации материалы доступны согласно настройкам доступа.

## 10. Копии и дальнейшие обновления

Сервис обслуживания создаёт ежедневные копии и хранит три последних архива на этом VPS. Скачивайте их на компьютер или в отдельное хранилище вместе с `.env.production`. GitHub содержит исходники и не заменяет копии учеников, попыток и материалов.

Команды скачивания резервных копий и обновления кода — в [DEPLOYMENT.md](DEPLOYMENT.md). Для установки из архива обновляйте исходники новым архивом; команды `git pull` применяются к установке через GitHub. Сохраняйте `.env.production` и именованные тома Docker. Команда `down -v` удаляет тома с базой и материалами.

Команда `init_platform` поставляется с этой версией исходников. Используйте актуальный архив, содержащий `learning/management/commands/init_platform.py`.
