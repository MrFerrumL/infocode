# Инфокод — платформа подготовки к ЕГЭ

**[infocode1.ru](https://infocode1.ru)** — закрытая учебная платформа преподавателя для своих учеников: ЕГЭ по **информатике** и **физике**. Ученик решает задачи всех номеров с проверкой прямо в каталоге, проходит курсы, конспекты и тренировочные варианты в формате экзамена. Преподаватель выдаёт работы, видит прогресс и ведёт расписание. Рядом работает отдельная платформа контрольных **«Инфокод · КР»**: вход по коду, без регистрации, с сигналами о списывании.

![Личный кабинет ученика](docs/screenshots/22-dashboard.jpg)

> Скриншоты сняты с локальной копии платформы с тем же банком задач. Имена учеников и названия групп на них вымышленные, история решений — демонстрационная.

Подробное техническое руководство (запуск, импорт, сервер, резервные копии) — [GUIDE.md](GUIDE.md).

## Что умеет платформа

### Каталог задач: решение прямо в списке

Выбор номера сразу показывает полные условия: открывать каждую задачу отдельно не нужно. Ответ проверяется на сервере, история попыток и разбор появляются в той же карточке. Доступны поиск по тексту и ID, фильтры по уровню (от «простого» до «гроба»), статусу, типу и источнику. Над условием стоит пометка источника: демоверсия, реальный ЕГЭ, ЕГКР, авторская задача.

![Каталог: номер 8](docs/screenshots/03-catalog.jpg)

Связанные задания 19–21 (теория игр) собраны в одну карточку с общим условием и тремя полями ответа; у каждого вопроса своя проверка и статистика.

![Задания 19–21 одной карточкой](docs/screenshots/04-catalog-games.jpg)

### Похожие задачи и «Тренировка дня»

Кнопка **«≈ Похожие»** раскрывает до пяти задач того же номера, близких по смыслу условия; сначала идут нерешённые. Связи заранее рассчитаны нейросетью `multilingual-e5-small` по текстам КЕГЭ и Полякова: модель не запускается при каждом ответе, на сервер приходит готовый индекс.

![Похожие задачи под карточкой](docs/screenshots/05-similar.jpg)

**Тренировка дня** — личный набор из 8 задач, который не меняется в течение дня. Он строится так: похожие на последние ошибки, затем слабые номера (меньше 80% верных за 90 дней), новые темы и повторение. Рядом с каждой задачей написано, почему она выбрана.

![Тренировка дня](docs/screenshots/06-daily.jpg)

### Подборки

Для каждого номера три шага: «знакомство», «на подумать», «повторение» (по 10 задач, в повторении — задачи реальных экзаменов). Подборки решаются на странице с прогрессом ученика. Рядом стоят ссылки на подборки Яндекс Учебника; подборки, сохранённые преподавателем, импортируются и решаются уже на платформе.

![Подборки](docs/screenshots/07-collections.jpg)

### Варианты и экзаменационная станция

Архив вариантов разложен по учебным годам и авторам. Вариант можно пройти «как на экзамене»: увеличенное условие, навигация по 27 номерам, файлы, составные ответы по ячейкам. Таймер ведёт сервер, поэтому закрытие вкладки его не останавливает. Баллы считаются по правилам КЕГЭ: №1–25 по одному первичному баллу, №26–27 до двух с частичным зачётом, затем перевод в тестовые баллы.

![Варианты по годам](docs/screenshots/08-variants.jpg)

![Экзаменационная станция](docs/screenshots/09-exam.jpg)

### Курсы и конспекты из Colab

Курсы строятся как **курс → раздел → урок → шаг**. Шаг может содержать теорию, фото, видео, Python, тест с разными типами вопросов или практику. Есть черновики, предпросмотр, версии содержания и защита от правки в двух вкладках сразу.

![Курс](docs/screenshots/10-course.jpg)

Конспекты собираются из ячеек или импортируются из **Google Colab** (`.ipynb`) — с Markdown, таблицами, картинками, кодом и его сохранённым выводом. Так перенесён учебный блокнот на 1 786 ячеек с разбором задач Полякова.

### Кабинет преподавателя

Главная показывает очередь проверки, ближайшие сроки и учеников с просроченными работами. Отсюда же создаются курс, задача и вариант.

![Кабинет преподавателя](docs/screenshots/02-teacher-home.jpg)

Ученики создаются в два клика: логин генерируется из имени, пароль — автоматически, карточку доступа можно сразу передать ученику. По каждому видно число решённых задач, точность, прогресс курса и последнюю активность.

![Ученики](docs/screenshots/14-students.jpg)

Аналитика за период: число попыток, доля верных, первые и повторные попытки, ритм занятий по дням, таблица «номер × ученик» и список тех, кому нужна помощь.

![Аналитика](docs/screenshots/20-analytics.jpg)

Работа назначается в три шага: что (готовый вариант, генерация по номерам, конкретные ID) → кому и до какого срока → правила (попытки, показ ответов). После сдачи есть журнал, ручная проверка, CSV и печать условий с ключами.

![Назначение работы](docs/screenshots/21-assign.jpg)

## Отдельная платформа контрольных «Инфокод · КР»

Отдельный проект со своей базой и учётными записями, развёрнут по адресу [infocode1.ru/kr/](https://infocode1.ru/kr/). Задачи для КР берутся из банка Инфокода через закрытый API.

- Преподаватель указывает группу, число вариантов, время и сколько задач брать по каждому номеру. Платформа собирает варианты **без повторов задач** и копирует условия, файлы и ответы к себе, так что проведённая КР не зависит от дальнейших правок банка.
- Ученик вводит код КР, фамилию и имя — регистрация не нужна — и ждёт, пока преподаватель откроет работу. Соседи по списку получают разные варианты.
- Таймер и автосохранение работают и при обрыве связи. **Ученик не видит ни балла, ни верных ответов**, а после сдачи писать дальше не может.
- **Сигналы о списывании** приходят преподавателю сразу: ушёл со вкладки или в другое окно, скопировал или вставил текст, нажал PrintScreen. Их видно в таблице и в ленте, есть звуковой сигнал и, по желанию, сообщение в Telegram.

## Наполнение: откуда задачи

Каждый банк переносился по своему конвейеру: **исходные данные → проверка условий, ответов и файлов → снимки условий → упаковка с SHA-256 → пробный импорт → импорт**. Повторный импорт пропускает уже загруженное и не трогает правки преподавателя и историю учеников.

| Источник | Что сделано |
|---|---|
| КЕГЭ, №1–27 | 8 993 задачи и 145 вариантов. Условия сохранены снимками шириной 1920 px, чтобы таблицы, формулы и код выглядели как в оригинале. Файлы данных до 1,1 ГБ (№24) импортируются потоково. |
| Сборник К. Полякова | 6 843 задачи из DOC/PDF с авторской нумерацией, ответами из таблиц и ссылками на видеоразборы. Совпадения с КЕГЭ по содержанию и ответу исключены. |
| Открытый банк ФИПИ | 557 задач актуальных типов, которых нет в других банках. Ответ ученика проверяется через сервис ФИПИ, верные ответы запоминаются; если ФИПИ недоступен, ученик видит понятное сообщение, а не ошибку. |
| Физика | 217 собственных задач, 6 конспектов, 36 подборок и 3 варианта, которые хранятся в репозитории и устанавливаются одной командой. |
| Яндекс Учебник | 73 ссылки на подборки; подборки, сохранённые преподавателем, импортируются и решаются на платформе. |
| Google Colab | Импорт `.ipynb`: Markdown, картинки, код и его вывод. |

## Архитектура

```mermaid
flowchart LR
    U[Ученики и преподаватель] -->|HTTPS| C[Caddy<br/>TLS, обратный прокси]
    C -->|/| W[web<br/>Django + Waitress]
    C -->|/kr/| K[kr<br/>платформа КР, Django]
    W --> DB[(PostgreSQL 16)]
    W --> M[(медиа: условия,<br/>файлы, видео)]
    M2[maintenance<br/>просроченные попытки,<br/>напоминания, копии] --> DB
    K -->|API по токену| W
    K --> KDB[(SQLite КР)]
    W -.->|проверка ответа| F[ФИПИ]
    K -.->|сигналы| T[Telegram]
```

- **Один Django-проект, два предмета.** Предмет текущего запроса хранится в `contextvar`, middleware ставит его из сессии. Стандартные менеджеры моделей фильтруют темы, задачи, варианты, подборки и курсы по предмету, а общие сущности (пользователи, группы, расписание) остаются едиными.
- **Docker Compose на VPS:** `db`, `migrate` (миграции до старта), `web` с проверкой здоровья, `maintenance` (фоновые задачи и ежедневные копии), `caddy` (сертификаты Let's Encrypt). Платформа КР — отдельный compose-проект в той же сети.
- Интерфейс отрисовывается на сервере: шаблоны Django и небольшие собственные скрипты. Без JavaScript работают и формы, и ответы.

## Интересные инженерные задачи

- **Обновление, которое переживает обрыв SSH.** Установщик загружает пакет, делает резервную копию данных, медиа и кода, запускает серверный сценарий отвязанно (`nohup setsid`) и следит за его журналом до строки с кодом завершения. Хранятся три последние копии каждого вида.
- **Резервные копии с проверкой.** Архив содержит данные, пользователей и медиа с манифестом SHA-256. Целостность проверяется после создания, старые копии удаляются только после успешной проверки новой. Восстановление выполняется только в пустую базу.
- **Импорт гигабайтных файлов** потоком, без загрузки в память; лимиты — 50 МБ на файл задачи и 3 ГБ на пакет.
- **Нейросетевые рекомендации без нейросети на сервере:** эмбеддинги считаются отдельно, на сервер попадает сжатый индекс связей (12 384 задачи, ≈138 тыс. связей).
- **Проверка ответов через внешний сервис** с кешем сессии (20 минут) и результатов (24 часа). Верный ответ запоминается, поэтому следующая проверка того же ответа уже не обращается к ФИПИ.
- **Честный экзамен:** время считает сервер, просроченные попытки закрывает обслуживающий процесс, разбор открывается по правилам варианта.
- **Две платформы, одна база задач.** Платформа КР не читает базу Инфокода напрямую: она обращается к API только для чтения с токеном, который собирает варианты без повторов, и копирует задачи к себе.
- **Безопасность:** хеши паролей, CSRF, ограничение попыток входа по логину и IP, серверная проверка ролей и владельцев, выдача файлов через защищённые обработчики, нейтрализация формул в CSV-выгрузках.

## Качество и эксплуатация

- **387 автотестов** на отдельной тестовой базе плюс проверки `manage.py check`, `makemigrations --check` и GitHub Actions с PostgreSQL и сборкой контейнеров (`.github/workflows/checks.yml`).
- `check_content --strict` проверяет рабочую базу без изменений: миграции, наличие всех прикреплённых файлов, условия опубликованных задач, слайды уроков, место на диске. Запускается после каждого обновления.
- Журнал ошибок HTTP с маршрутом и временем ответа, `/health/` для Docker.
- Пароли, ключи, база и доступы учеников в Git не попадают.
