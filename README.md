# Инфокод

Рабочая первая версия платформы подготовки к ЕГЭ по информатике. Серверная логика написана на Python (Django), интерфейс — HTML, CSS и небольшой JavaScript для визуального редактора, автосохранения и перестановки блоков. Node.js для запуска не требуется. По умолчанию данные сохраняются в SQLite, файлы — на диске; предусмотрена конфигурация PostgreSQL.

## Ученики, сервер и GitHub

- [STUDENTS.md](STUDENTS.md) — выдать ученику логин и временный пароль, сбросить доступ, пригласить группу на самостоятельную регистрацию.
- [DEPLOYMENT.md](DEPLOYMENT.md) — сервер с HTTPS и PostgreSQL, перенос текущих учеников/материалов, резервные копии, ориентир стоимости.
- [GITHUB.md](GITHUB.md) — загрузить исходный код в приватный репозиторий; данные учеников и секреты исключены из Git.

В кабинете **Ученики → Создать ученика** преподаватель выдаёт готовый аккаунт. При первом входе ученик меняет временный пароль. В карточке ученика есть **Выдать новый пароль**. По приглашению в группу ученик может зарегистрироваться сам и прикрепиться к преподавателю.

## Быстрый запуск

Установите Python 3.12 с официального сайта https://www.python.org/downloads/ (также поддерживаются Python 3.10–3.13). Распакуйте проект, откройте терминал в его папке и выполните:

```powershell
python start_local.py
```

В Windows, если команда `python` недоступна, используйте `py start_local.py`.

Первый запуск создаст изолированное окружение `.venv`, установит зависимости, подготовит базу и примеры. Нужен интернет для установки пакетов. Откройте **http://127.0.0.1:8000/**. Логин администратора — `admin`, случайный пароль появится в терминале и в локальном файле `.local-credentials.txt`. Пароль можно изменить в кабинете. Пользователи регистрируются сами и всегда получают роль ученика.

При повторном запуске существующие пользователи, задачи и результаты сохраняются. Для остановки нажмите Ctrl+C. Порт 8000 должен быть свободен.

Локальная версия, подготовленная в текущей рабочей папке, уже имеет отдельные демонстрационные аккаунты. Их данные находятся в соседнем файле «Доступ к платформе.md». В распространяемый ZIP они не включены.

## Что работает

- Кабинет с боковым меню: Главная, Курсы, Банк задач, КР и задания, Ученики. В «Ещё» доступны аналитика, группы, медиатека, импорт, дубликаты, корзина, история и полная админка. Светлая/тёмная тема, меню для телефона, переключение на кабинет ученика.
- Главная преподавателя показывает реальные задания на проверку, ближайшие сроки, черновики курсов и учеников с незачтёнными работами после срока. Есть общий раздел проверки ручных решений и просмотра Python-кода из КР, с поиском и страницами.
- Назначение работы в три шага: содержание → ученики и сроки → правила и отправка. Доступны готовый вариант, генерация по номерам и выбор ID задач. При ошибке формы открывается нужный шаг; без JavaScript видна полная форма.

- Python-код в ответах учеников: преподаватель включает его для отдельных задач и проверяемых шагов курса, выбирая необязательный или обязательный режим. Код сохраняется вместе с ответом, доступен в истории и преподавателю, поддерживается в вариантах и обязательных КР. Исполнение и автоматическая проверка программ не реализованы; обычный ответ проверяется как раньше.
- Каталог всех 27 номеров: поиск по тексту и ID, фильтры сложности и статуса, разбор после попытки, файлы к задачам. Пять уровней: Простой, Средний, Сложный, ЕГЭ, Гроб.
- Отдельные конструкторы условия и разбора: заголовок, текст, изображение, файл и Python-код в любом порядке. Текст необязателен. Фото условия, текст, фото и файл разбора, код можно добавить сразу при создании задания. Код сохраняет отступы и отображается без выполнения.
- Копирование заданий и блоков, фильтры банка по сложности и публикации. Файлы разбора закрыты до первой попытки, в варианте — до сдачи. Варианты сохраняют снимок условия и разбора, включая файлы и код.
- Проверка коротких ответов на сервере, история попыток, избранное, список ошибок и прогресс по каждому номеру.
- Сборка вариантов случайным выбором по номерам или вручную по ID. Можно выбрать 1–3 задачи каждого номера, сложность и длительность.
- Контрольные по темам используют тот же конструктор, но находятся в отдельной вкладке.
- Группы учеников и назначение работ группе. Черновики недоступны ученикам.
- Экзаменационный режим: серверный срок сдачи, сохранение ответов, продолжение попытки, повторные попытки, результаты и разборы после сдачи.
- Кабинет преподавателя: добавление задач, публикация работ, результаты учеников, экспорт CSV, печать условий и ключей через Ctrl+P / «Сохранить как PDF».
- Полная админка Django: редактирование задач и 27 тем, пользователи, группы, разделы и уроки курса.
- «Мои ученики»: прикреплённые ученики, активность, правильные ответы, прогресс по 27 номерам, история работ и шагов курса.
- Несколько курсов со структурой «курс → раздел → урок → шаг». Автор задаёт порядок: например видео, тест, теория, файлы. Шаги поддерживают текст с иллюстрацией, MP4/WebM, выбор одного или нескольких ответов, короткий ответ, скачивание файла. Видеоплеер поддерживает перемотку и полный экран; доставка видео — HTTP Range.
- Редактор курса: обложка, описание, группа, публикация, перестановка разделов, уроков и шагов, предпросмотр, баллы, лимиты попыток и отчёт CSV.
- Формы шагов показывают поля выбранного типа. Тесты редактируются строками с галочками правильных ответов: один ответ, несколько ответов, шаблон «верно / неверно». Есть добавление и удаление вариантов, сохранение незавершённого теста в черновик, кнопка «Сохранить и посмотреть».
- Свободный конструктор урока: любые последовательности и повторения слайдов, например тест → практика → практика. Теория, фото, видео и проверяемое задание на одном слайде; тип задания меняется в общем редакторе. Копирование шагов, уроков, модулей и курсов в черновики; ответы и прогресс не копируются. Обзор курса показывает количество шагов, черновиков и пустых уроков.
- В генераторе вариантов и назначении КР можно включить Python-код сразу во всех заданиях: необязательный, обязательный или индивидуальные настройки банка. Ученик пишет код или импортирует .py; преподаватель открывает отправленные программы через результаты в карточке КР и получает уведомление о сдаче. Программы не запускаются.
- Учебный экран с программой слева и шагами сверху: запись на курс, продолжение обучения, индивидуальный прогресс, история ответов, разборы и обсуждение с модерацией.
- Урок завершён, когда пройдены все его опубликованные шаги текущих версий. Изменение содержания шага требует повторного прохождения; история прежних ответов сохраняется.
- Адаптивный интерфейс, в том числе для телефонов.

## Наполнение

Команда `seed_demo` добавляет **81 авторскую вводную задачу**, по три на каждый номер, **6 текстовых уроков с тестами и конспектами**, один вариант и две контрольные. Повторный запуск не перезаписывает существующие материалы.

Это демонстрационное учебное наполнение, а не полноценный официальный банк ЕГЭ. Примеры намеренно небольшие и относятся к базовой сложности. Номер 12 иллюстрирует преобразования строк; структуру задач и курс необходимо адаптировать под спецификацию выбранного года. Упражнения по играм также упрощены для знакомства с механизмами платформы. Нет заявления, что примеры повторяют формат актуального КИМ.

**Готовых видеозаписей нет.** Видеоуроки нужно записать или загрузить свои материалы, на использование которых у вас есть права. Демонстрационный курс содержит текст, тесты и конспекты. Полный многомесячный курс и большая база экзаменационных задач — отдельное наполнение этой структуры.

## Работа преподавателя

1. Войдите как администратор и откройте «Кабинет преподавателя».
2. В «Банке заданий» создайте задание: заполните название, номер, сложность и ответ. В разделе «Условие» напишите текст или выберите фото. В разделе «Разбор» добавьте текст, фото, файл и/или Python-код. Всё можно сохранить одной кнопкой. Ниже появятся отдельные группы блоков условия и разбора: добавляйте новые блоки и меняйте порядок стрелками. Пустое условие опубликовать нельзя; при удалении последнего блока условия пустая задача снимается с публикации.
3. «Создать вариант»: отметьте номера, выберите количество и время. Для ручной сборки укажите ID, например `1, 8, 20`; в этом режиме фильтры по номерам и сложности игнорируются. Если задач недостаточно, система сообщит об этом и не создаст неполную работу.
4. Для КР выберите тип «Контрольная по темам». Снимите флажок публикации, чтобы оставить черновик.
5. Через «Ученики и группы» создайте группу и добавьте зарегистрированных учеников. При создании работы выберите эту группу; без группы опубликованная работа доступна всем ученикам.
6. Откройте «Курсы»: создайте курс, раздел и урок. Выберите карточки слайдов в любом порядке и сохраните урок. Слайды создаются черновиками. «Теория + задание» совмещает материалы и проверку на одной странице. Для каждого шага заполните материал. В тесте введите варианты в отдельные поля и поставьте галочки у правильных. Выберите один или несколько ответов, настройте баллы и число попыток (0 — без ограничения). Кнопка «Ещё вариант» с включённым JavaScript добавляет строку без перезагрузки и потери выбранных файлов. Опубликуйте курс, урок и нужные шаги. Черновой тест без правильного ответа можно сохранить, но опубликовать нельзя.
7. Откройте «Мои ученики». Суперпользователь может прикрепить зарегистрированного ученика к себе на этой странице; назначения другим преподавателям доступны в полной админке через «Назначения учеников». Откройте карточку ученика для подробного прогресса.
8. Проверяйте результаты работ в кабинете преподавателя, результаты курса — в его отчёте. Ключи и версия для печати доступны только преподавателю.

Сотрудники с `is_staff` — преподаватели одной школы. Банк заданий и работы общие; персональная статистика учеников доступна назначенному преподавателю, суперпользователь видит все результаты работ. Редактировать курс и смотреть его отчёт может автор или суперпользователь. Доступ к встроенной админке дополнительно регулируется разрешениями Django. Это не SaaS с изоляцией независимых школ.

Учебный интерфейс использует знакомую по Stepik структуру и основные сценарии обучения. Полное функциональное соответствие Stepik не заявляется: оплаты, сертификаты, прокторинг, автоматическая проверка программ в изолированной среде и маркетплейс не реализованы. Просмотр видео и чтение материалов подтверждаются кнопкой ученика; фактическое время просмотра не отслеживается.

## Обновление существующей установки

Остановите сервер и сохраните резервную копию `db.sqlite3`, `uploads/` и `.local-secret`. Обновите исходники, сохранив эти данные. Затем запустите `python start_local.py`: зависимости, миграции и статика обновятся автоматически. При ручной установке выполните установку `requirements.txt`, `manage.py migrate` и `manage.py collectstatic --noinput`, затем запустите `serve.py`.

Миграции сохраняют старые задачи, переносят прежние уроки в курс с шагами и сохраняют пройденные уроки. Существующие ученики первоначально прикрепляются к первому суперпользователю; назначения можно изменить в админке. Старое текстовое условие и вложение становятся блоками при сохранении задания в новом редакторе.

## Как проверяются ответы и время

- Ответы сравниваются без учёта регистра, лишних пробелов и переносов строк; Unicode приводится к NFKC. Ведущие нули и порядок чисел сохраняют смысл. В задачах на набор чисел нужно явно указать порядок в условии.
- Сложные ответы, частичные баллы и официальный перевод в стобалльную шкалу не реализованы. Результат — число полностью верных ответов; это явно обозначено ученику.
- Условия, ответы, разборы и ссылки на файлы фиксируются при создании варианта. Последующие изменения исходных заданий не меняют уже выданную работу.
- Срок сдачи хранится на сервере. Закрытие браузера не останавливает время. Поздняя отправка не заменит сохранённые ответы.
- Сохранение выполняется кнопкой «Сохранить ответы»; автоматического сохранения при наборе нет. Остаток минут обновляется при загрузке страницы. Это относится к ответам варианта; у редакторов преподавателя есть отдельное автосохранение черновика.
- Истёкшая попытка завершается при открытии работы, кабинета ученика, прогресса или кабинета преподавателя. Для фонового завершения независимо от посещений запускайте каждую минуту `python manage.py expire_attempts` планировщиком сервера.
- Статистика каталога отражает именно практику; результаты вариантов показаны отдельно в истории работ.

## Ручная установка

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python manage.py migrate
.venv\Scripts\python manage.py createsuperuser
.venv\Scripts\python manage.py seed_demo --owner YOUR_ADMIN_LOGIN
.venv\Scripts\python manage.py collectstatic --noinput
.venv\Scripts\python serve.py
```

На Linux/macOS замените `.venv\Scripts\python` на `.venv/bin/python`. Можно не запускать `seed_demo`, если нужна пустая база. В этом случае добавьте темы 1–27 через админку.

## Публикация на сервере

Платформа сейчас запущена **локально**, публичного адреса нет. Django требует Python-хостинга или VPS. Встроенный хостинг Sites рассчитан на Cloudflare Worker-совместимые приложения, поэтому этот Python-проект туда не публиковался.

Включены `Dockerfile` и `compose.yaml`. Пример развёртывания на VPS:

1. Скопируйте `.env.example` в `.env`, задайте уникальный `SECRET_KEY`, домен в `ALLOWED_HOSTS` и HTTPS-адрес в `CSRF_TRUSTED_ORIGINS`. В Docker Compose `.env` загружается автоматически; при обычном запуске экспортируйте переменные в окружение процесса сами.
2. Выполните команды:

```bash
docker compose build
docker compose run --rm web python manage.py migrate
docker compose run --rm web python manage.py createsuperuser
docker compose run --rm web python manage.py seed_demo --owner YOUR_ADMIN_LOGIN
docker compose up -d
```

3. Настройте Nginx или Caddy перед `127.0.0.1:8000` с HTTPS. Прокси должен сам устанавливать `X-Forwarded-Proto`, а не принимать его от клиента. `DEBUG=0` включает HTTPS-перенаправление и защищённые cookie. Настройте допустимый размер загрузки видео до 500 МБ и ограничение частоты запросов входа/регистрации на прокси.
4. Сохраняйте резервные копии базы, папки загрузок и секретов. Для согласованной копии SQLite используйте механизм backup SQLite либо остановите приложение на время копирования.

SQLite остаётся удобным вариантом для локального запуска. Для сервера подготовлены `requirements-postgres.txt` и `compose.postgres.yaml`: переменные DB_ENGINE, DB_NAME, DB_USER, DB_PASSWORD, DB_HOST, DB_PORT. Перед размещением настройте HTTPS, секреты, резервное копирование и доставку больших видео. Docker/PostgreSQL на реальном VPS и нагрузка 100 одновременных пользователей в текущей среде не проверены.

Защита приложения включает хеширование паролей Django, CSRF, серверные проверки роли и владельца попытки, экранирование пользовательских текстов, ограничение форматов и размеров вложений, закрытую выдачу файлов, нейтрализацию формул в CSV. Ученик не может получить ключи экзамена через страницы вариантов до сдачи. Платформа не является системой прокторинга: параллельное использование каталога и сторонних ресурсов не блокируется.
