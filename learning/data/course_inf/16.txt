=== theory: Как считать рекурсивные функции
<p>Функция задана рекуррентно: для маленьких n значение известно, а для остальных выражается через значения той же функции от других аргументов. Нужно найти значение при каком-то n или выражение из нескольких значений.</p>
<h3>Перенос определения в Python</h3>
<p>Определение переписывается почти дословно: каждая строка «F(n) = … при …» — ветка <code>if</code>.</p>
--- code
from functools import lru_cache

@lru_cache(None)                 # запоминает уже посчитанные значения
def H(n):
    if n <= 2:
        return 1
    if n % 2 == 1:
        return H(n - 1) + 2 * H(n - 2)
    return H(n - 1) - H(n - 2) + n

print(H(20))                     # 12028
--- end
<p>Без <code>lru_cache</code> такая функция вызывает себя дважды на каждом шаге, и при n порядка 40–50 счёт затягивается на минуты. С запоминанием каждое значение считается один раз.</p>
<h3>Большие аргументы</h3>
<p>Если n — тысячи, Python останавливается с ошибкой <em>RecursionError</em>: глубина вызовов ограничена. Есть три выхода.</p>
<ol>
<li><strong>Посчитать снизу вверх циклом</strong> — самый надёжный способ, стек не нужен.</li>
<li>Заполнить кеш постепенно: вызвать F(1), F(2), … по порядку, тогда каждый следующий вызов неглубокий.</li>
<li>Увеличить предел: <code>sys.setrecursionlimit(10000)</code> — работает, но при очень больших n программа может упасть.</li>
</ol>
<h3>Пример: алгебра вместо вычислений</h3>
<p>F(1) = 1, F(n) = n · F(n − 1) при n &gt; 1. Найдите (F(2025) + 2 · F(2024)) / F(2023).</p>
<p>F(2025) = 2025 · 2024 · F(2023), F(2024) = 2024 · F(2023). Делим: 2025 · 2024 + 2 · 2024 = 2024 · 2027 = <strong>4 102 648</strong>. Программа подтверждает — Python спокойно работает с числами в тысячи цифр:</p>
--- code
F = [0, 1]                       # F[n] — значение функции, считаем снизу вверх
for n in range(2, 2026):
    F.append(n * F[n - 1])
print((F[2025] + 2 * F[2024]) // F[2023])    # 4102648
--- end
<h3>Частые ошибки</h3>
<ul>
<li>Перепутать условия веток: «при n &gt; 2 и чётном n» — проверяйте обе части.</li>
<li>Делить через <code>/</code>: для огромных чисел нужно целочисленное деление <code>//</code>, иначе получится неточная дробь.</li>
<li>Забыть, что функция может «идти вверх»: F(n) = F(n + 3) + 1 при n &lt; 100 — базовый случай тогда сверху.</li>
</ul>

=== quiz: Проверь себя: зачем lru_cache
? Зачем перед рекурсивной функцией пишут @lru_cache(None)?
+ Чтобы каждое значение функции считалось один раз и запоминалось
- Чтобы снять ограничение на глубину рекурсии
- Чтобы функция работала с большими числами
- Чтобы функция вызывалась только один раз
>> lru_cache запоминает результат для каждого аргумента: повторный вызов берёт готовое значение. Глубину рекурсии он не меняет — для неё нужны цикл или sys.setrecursionlimit. Большие числа Python поддерживает и так.

=== answer: Мини-задача
<p>Функция задана так: G(n) = 3 при n ≤ 2; G(n) = G(n − 1) + n, если n &gt; 2 и n чётное; G(n) = 2 · G(n − 2), если n &gt; 2 и n нечётное.</p>
<p>Чему равно G(15)?</p>
= 384
>> 15 нечётное, поэтому G(15) = 2 · G(13) = 4 · G(11) = … = 2⁷ · G(1) = 128 · 3 = 384. Нечётные аргументы ссылаются только на нечётные, чётная ветка не понадобилась.
